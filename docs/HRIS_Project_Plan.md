# 北森人力资源管理系统复刻项目规划 V1.4

日期：2026-09-07

## 1. 项目目标与范围口径

以用户提供的北森 iTalent 租户为参考，独立实现可运行、可维护的人力资源管理系统，覆盖界面交互、业务流程、数据持久化、权限控制及管理报表。先完成项目规划，再启动原系统盘点与开发。

当前仅收到系统入口和登录信息，尚未验证账号权限、已开通模块及实际页面。本文中的模块均为规划候选项，不代表已确认的北森功能。完整交付以盘点后的范围清单为准；不可访问的模块列入差异清单，不以推测宣称已复刻。

复刻对象为获授权可见的功能和使用体验；采用独立代码实现。原系统后端源码、未开放接口、专有测评模型及算法不在可直接复现的已知范围内。需要这些能力时记录依赖，采用明确标注的独立实现或合法接口集成。

用户已于2026-09-07明确最终目标：承载真实人事业务、投入生产使用。开发验证继续使用合成数据；完成生产验收后切换正式业务。

## 2. 执行原则

- 原系统仅做只读查看：导航、页面结构、字段、筛选、状态、帮助说明；不提交审批、不修改配置、不发送通知、不触发导出或批量操作。
- 登录凭据不写入项目文件、代码、日志、示例数据或新系统；登录只通过浏览器提供的认证能力。
- 使用合成人员与业务数据进行开发和测试，不把原租户员工、薪资、测评结果复制到新系统。
- 每项需求记录证据来源、观察日期、实现状态及验收用例，区分已观察、合理假设与待核实。
- 首页和模块菜单不等于完整系统；核心业务必须贯通列表、详情、编辑、状态流转、权限和持久化。

## 3. 候选模块与顺序

| 波次 | 模块 | 拟实现业务范围 | 验收重点 |
| --- | --- | --- | --- |
| A | 平台基础 | 工作台、导航、组织/用户/角色、数据权限、字典、审批、审计 | 角色与数据隔离、待办可追踪、变更有记录 |

| B | 招聘与入职 | 需求、职位、候选人、面试、录用、入职衔接 | 招聘到员工档案的闭环与重复校验 |
| B | 假勤管理 | 班次、考勤记录、请假、加班、异常处理 | 规则计算、审批、余额与记录一致 |
| B | 薪酬管理 | 薪酬项目、计算批次、复核、工资单 | 合成案例可复算、权限隔离；正式规则另行验证 |
| C | 绩效管理 | 周期、目标、评估、校准、结果确认 | 状态、权重、分值和查看范围正确 |
| C | 人才发展 | 能力标准、盘点、九宫格、继任、发展计划 | 人岗关联、盘点规则与后备计划闭环 |
| C | 学习管理 | 课程、项目、报名、学习记录、考试/评估 | 学习任务到完成记录、报表一致 |
| D | 员工/经理自助 | 个人档案、申请、审批、团队视图 | 各身份入口与实际数据权限一致 |
| D | 分析与配置 | 人事指标、人才报表、字段与流程配置 | 指标口径可解释、筛选与导出一致 |

实际启用模块以账号盘点结果调整。用户未提出只做人才发展模块，因此规划保留全系统范围，不以个人专业方向缩减范围。

## 6. 技术与数据设计

采用 Sites 支持的 Web 应用技术栈。初始架构选择模块化单体：统一界面组件与服务端业务层、关系型数据存储及迁移、私有访问。附件存储按实际需求启用。最终配置在初始化时按环境能力确定。

核心实体：组织、岗位、员工、任职记录、用户、角色、权限、流程定义、流程实例、审批任务、审计事件；扩展为候选人、职位需求、考勤、薪酬批次、绩效周期/评价、能力标准、盘点项目、继任计划、课程及学习记录。

所有业务数据关联组织或租户范围；权限在服务端校验，不依赖前端隐藏菜单。审批使用明确状态机并防止重复处理；涉及金额与评分的计算保留规则版本。浏览器本地存储仅承载界面偏好，不作为业务持久化数据库。

## 7. 统一验收标准

1. 范围：盘点清单逐项对应已完成、受限或待实现状态；不得以空壳页面报完成。
2. 界面：按可见参考核对导航、布局、密度、字段和关键状态；无参考部分明确标注独立设计。
3. 功能：列表筛选、详情、表单校验、保存、审批与异常反馈按需求运行。
4. 数据：刷新和新会话后数据仍在；关联一致；重复请求不产生重复业务记录。
5. 权限：员工仅见本人，经理按授权见团队，HR 按范围管理；直接访问接口同样限制越权。
6. 跨模块：录用转入职、人员异动更新组织关系、流程生成待办、结果进入对应报表。
7. 质量：关键流程自动化验证与浏览器实测；覆盖空数据、非法输入、拒绝/撤回、重复操作和加载失败。
8. 交付：源码及版本、数据迁移、合成测试数据、部署状态、使用说明、差异清单齐备。

## 14. P3顺序确认与首批实施

用户已确认调整顺序：组织与员工 → 干部与人才发展 → 学习管理 → 绩效 → 招聘与入职 → 假勤 → 薪酬社保 → 自助完善、报表与集成。无需再次确认该顺序。

实施依赖：第1模块先交付岗位/职级、任职关联、人员状态、权限和必要附件基础。干部人才模块先做标准与岗位要求，再做人才档案、盘点/继任/发展计划；历史绩效采用可追溯导入，不虚构缺失分值。学习先具备课程与学习记录，再联动岗位能力差距和发展计划。合同、编制等可继续迭代，不阻塞人才发展起步。

本轮交付：岗位目录（含组织、岗位族、职责）、职级体系、员工关联岗位与职级；调动流程支持同组织的调岗/调级，最终通过才写入人员档案及任职历史。在职和待审批引用阻止目录停用/改标识。目录关联通过同租户外键约束。历史自由文本不擅自自动匹配目录；首次关联名称不一致须通过调动审批。联系邮箱/职级字段权限继续适用。

验证：20项既有规则与集成场景回归，加1项岗位职级端到端集成场景，覆盖目录—员工关联—禁止直接调级—申请—在用保护—终审生效—历史记录。当前模块1仍在推进，必要附件能力及后续人才模块尚未在本轮完成。

上述新增流程为独立实现方案，尚未逐页核实为原租户相同规则；原站详细盘点仍需随模块实施补充。
