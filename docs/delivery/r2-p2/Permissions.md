# R2权限、回避与敏感数据

<a id="authorization"></a>
## 服务端授权模型

复用R1 grant tuple：对象种类、动作、人员/组织/岗位/项目/池范围、字段集合、关系类型、时间/历史用途。先对每一个完整grant求允许对象字段，再求并集，最后与敏感策略/当前身份/离职及安全撤权屏障相交。禁止把角色A的人员范围与角色B的敏感字段拼接；管理员、HR不是自动全字段角色。每页、详情、搜索、筛选、排序、汇总、导出、附件和历史接口均执行同一计划。

本人只由当前有效member→person绑定确定，客户端personId不能替换本人；解绑或停用立即阻新读写和下载。经理只获取显式直线/虚线/间接关系grant，不从职称推定全下级；关系缺失为未配置。旧关系快照只解释历史，不授当前权限。HR需当前对象及人员/岗位范围；委员会按议程、期次、最小字段和有效时间授权；运维只能技术元数据，内容解密需受控用途授权。只读角色不继承导出、审核或发布。

<a id="recusal"></a>
## 自审、回避和授权生命周期

每applicationVersion冻结subjectIds、submitterId、materialContributorIds（含此前版本实质材料贡献人）、reviewerSet及recusalDecisionRefs。所有审批动作排除本人、申请人及该内容的实质贡献者；操作员仅传输未改内容时以独立操作审计区分，但不能伪报“代录”来删贡献者。M18复核人与发布人不同；M17本人不能唯一指导者或最终核验者；M03任用核对独立授权且不得由本人/提名贡献者自核。节点改派须合法模板、理由、新节点版本及审计；D7不得转交/干预/委托/会签。

委员会回避通过独立管理员/流程批准变更显式eligible set，已完成评价不在原期次无痕删除。缺合格人数或缺业务阈值阻启动/决议，不能因回避自动通过。投票弃权与未提交分开；具体分母由M06/M18/M03各自规则决定，不通用化强行统一。

授权撤回先提交独立安全账本deny并递增securityEpoch，再同步业务投影；grant仅双端确认后激活。缓存key含tenant/actor/authRevision/purpose/version，401/403、epoch变化或解绑时清空敏感缓存，晚到响应不能恢复。服务中断只允许带时点的非敏感摘要，M26报告、候选名单、访谈原文无stale回退。此机制继承R1；P3若未交付，相关敏感读取保持禁用，不另建弱授权旁路。

<a id="anonymity"></a>
## M26身份隔离与防差分

邀请运营表存reviewerPersonId/发送状态；答卷存opaqueResponseId/subjectId/roleVersion/答案版本。两者桥接表分离存储策略和专用受控访问动作，不进入普通development事件、查询索引、下载URL、日志或M32 join目录。提交回执仅给答题者本人；HR邀请完成状态不能联查逐题内容、时间排序或报告原始文本。对运维技术账户不许通过常规读权限解密答卷；密钥由R1独立控制域管理，仍须P4核验实际平台隔离能力。

匿名每组至少3名不同有效评委，阈值可升不可降。低于阈值不返回分数、精确人数、原话和可相减余项；不把低样本组静默并组。本人和明确唯一直属经理可列实名组，必须明示性质且不混匿名分母。至少一组合格非本人反馈才允许报告发布；组织汇总至少3名被评价人，并仍检查底层匿名组。

固定发布维度、固定cohortManifest和releasePolicyVersion，不开放任意人员筛选/交叠小群统计。服务记录租户范围的披露账本（cohort集合用受保护ID，不向分析者公开），把所有潜在可共同获得的发布版本视为可联结；同报告更正或跨报告重叠时计算集合差集及补集，任一0以外小于阈值或可隔离个人贡献则抑制受影响单元和总计。精确均值与样本数的组合也视为可披露量；算法不能证明安全则拒绝该维度发布，保留未抑制的固定合法组。P3专门构造交叠/更正探测；这不是数学上对所有外部先验的绝对匿名保证，P4独立隐私复核用途与实际知情范围。

自由文本发布前用独立已授权人工脱敏结果及其版本，原话默认不传播；可识别内容或无复核证据为withheld。任何未来自动AI脱敏/测评均不在范围。报告更正不能撤回已下载字节；旧链接即时deny，新报告重新执行阈值、受众和历史披露检查，不能利用反复开关项目泄露单人增量。

<a id="files"></a>
## 附件、下载、审计

附件必须有tenant、objectType/rootId/versionId、purpose、classification、owner policy、MIME、size、sha256和不可变存储key；默认继承R1 10MiB及既有MIME白名单，超限拒绝，新增类型需显式schema。先写不可见对象，再同业务事务绑定manifest/审计；失败为orphan，不宣称可下载。禁止泛型ownerId或知道key即下载。

下载在对象获取前后均核current read及相应export/download、version状态、securityEpoch，禁止公开或长期可绕权URL；撤权/墓碑立即禁读。恢复点仍引用的字节不可物理清理，业务历史不因30天备份窗口删除。已下载副本无法技术保证回收，追溯访问日志和后续用途责任保留。

业务审计仅记录对象、版本、动作、执行人、来源/结果码、权限决策摘要、digest及安全引用；不包含答卷、评委桥接、面试原文或纪律内容。原始材料在独立对象授权域；审计read不授材料read。审计事件、outbox、版本和恢复日志原子落库；日志/监控禁止敏感payload。备份密文、元数据及密钥权限与在线读取同等约束。

匿名谱系、跨受众/用途账本和安全分区按[002精确规范](Anonymity_Repair.md)；伪名/系数/原子manifest为restricted，普通报告和HR无读取权。
