# 恢复演练基线

## 当前证据

`node scripts/rehearse-local-recovery.mjs` 只创建临时合成 SQLite 数据库和内存对象存储，执行后删除临时数据库。它不会连接线上 D1/R2，不接受线上数据库路径，不读取真实人员文件。结果在 Recovery_Synthetic_Report.json。

本地演练已验证：迁移文件与19张表指纹、数据库完整性、外键、应用查询内容和修订、附件内容与校验和、附件缺失及损坏识别、未授权账号拒绝、恢复后的审计写入；已定版绩效模板及周期快照、恢复后拒绝修改定版、已领取并在备份前停用账号对绩效和附件仍拒绝。当前12张表有合成行，其他表只验证结构及空集一致性。业务恢复点之后新增的记录不出现在恢复结果中。

快照前假设暂停写入，数据库和对象清单来自同一静止窗口。脚本包含的毫秒耗时只是本地小数据复制及核对时间，不是企业RTO。没有验证云端备份调度、加密、保留、跨区恢复或生产RPO。

## 正式环境演练前的工作

1. 确认目标环境、负责人及可用的D1/R2备份恢复能力，记录数据库、附件、应用源码版本和迁移校验和的对应关系。
2. 制定一致性窗口及写入控制：如不能静止写入，须另行实现并验证跨数据库与对象存储的一致性方案。
3. 将数据库备份和附件对象版本、大小、哈希清单一起保存；不能仅备份数据库中的附件元数据。
4. 在隔离恢复环境恢复对应应用和迁移版本，核对全部表、业务状态、权限、审批与审计、附件数量和内容；额外检查缺失对象、损坏对象、孤立对象与删除标记。
5. 开放访问前，将成员、角色、组织范围和停用状态与独立可信的当前授权记录对账。备份后的离职、停用或撤权可能不在旧快照中，不能因旧快照曾允许就重新开放；没有可信对账来源时保持恢复环境隔离，不以原备份作为“当前授权”证据。
6. 用企业代表性流程检验恢复后的读取与新写入，再按实际数据量记录恢复点和耗时。
7. 对照企业确认的RPO/RTO验收。正式生产切换、真实迁移及扩大访问范围另行确认，当前本地演练不授予这些操作权限。

实际云端恢复与全业务恢复仍未验收，不能将本报告标成生产就绪。当前可继续开发，不需要用户为合成演练重复审批。
