## 2. 验证方式

- `npm run test:p2`：20项测试，含17项业务/权限/流程规则测试及3组真实路由集成测试。三组集成场景内部覆盖多个成功和失败路径。
- 测试通过Node SQLite执行生成的迁移及应用实际生成的SQL；仅模拟平台身份头和D1调用封装，不用手写替代业务处理函数。
- 涵盖：拒绝越权、字段权限、重复初始化、流程版本、越级审批、员工状态更新、历史记录、权限停用、迁移重入、过期版本拒绝、跨租户外键、业务失败回滚、审计失败回滚。
- 原SQL字符串提取测试已由真实路由和持久化层集成测试替代。
- 部署前读取线上数据库：尚无企业工作空间，因此无需迁移既有线上业务记录。发布后须核对新增表已应用。

## 3. 当前权限口径

| 角色 | 数据范围 | 可操作内容 |
| --- | --- | --- |
| 系统管理员 | 当前企业 | 企业成员/范围/字段授权、流程配置、组织员工、人事申请、分配给自己的审批、审计 |
| 人事管理员 | 授权组织及下级 | 范围内组织和员工维护、人事申请；字段受独立授权限制 |
| 部门经理 | 授权组织及下级 | 团队查看、申请、分配给自己的审批；字段受独立授权限制 |
| 审批人 | 授权组织内分配给自己的记录 | 对应员工基础查看和当前节点审批；字段受独立授权限制 |
| 员工 | 本人 | 本人档案、申请和任职历史；字段受独立授权限制 |

角色权限不替代站点本身的访问授权。没有配置组织范围的非管理员默认不能查看该范围人员；管理员需明确授权。联系邮箱和职级的“可维护”仍受角色能力限制，员工、经理和审批人不会因为字段可见而获得档案编辑权。

## 4. 与后续阶段的边界

- P3尚未实现的完整组织员工业务：职务/岗位体系、编制、合同附件、自定义字段、入职完整流程等；现有job/level为基础任职字段。
- 当前字段权限覆盖现有字段中的联系邮箱与职级；后续薪酬、证件等字段在对应模块中扩展。
- 当前组织与员工主界面采用已授权数据的客户端分页；任职历史和审计采用服务端分页。大规模企业的全量主数据查询优化、容量和负载验收在P4完成。
- 无正式薪酬、社保或税务规则验收；无企业SSO接入；无真实员工数据迁移、容灾或备份恢复演练。
- 目前验证为自动化接口联调及数据库验证，未进行真人多账号浏览器端到端验收。
- 旧数据迁移只对已有数据建立任职基线，不虚构升级前缺失的历史。保留快照用于核对，不承诺直接降级到旧版；降级可能丢失升级后的变化，需走正式恢复流程。
