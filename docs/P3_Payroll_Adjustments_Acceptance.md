# 工资条异议与补差首轮验收

更新：2026-09-07

## 业务流程

员工本人可针对已发布工资条提出异议，同一工资条只能有一个待答复异议；员工可撤回待答复异议。薪酬管理人员答复，可关联本工资条已发布补差；不能将未发布记录作为关联处理结果。当前薪酬管理角色仍为管理员，普通HR或经理不自动获得工资访问权限。

差额台账引用原工资条，以整数分登记已核定的正负应发、个人扣款或企业承担项目。正个人扣款减少实发，负个人扣款增加实发，企业承担不影响实发。编制人不能复核，受益本人不能编制、复核或发布。一次仅一个在途补差，批准后可发布，已发布不可修改或取消；错误通过新建反向记录再次复核更正。

累计值等于原工资条加全部已发布差额，不含待审/批准未发布记录。负差额属于台账记录，不代表已从员工收回资金；发布不执行付款、扣款、银行代发、税费计算或申报。当前没有跨计薪期间自动结转逻辑。

## 数据隔离

员工仅见本人已发布差额，内部来源和企业承担项目不返回；普通HR、经理、审批人员看不到异议和差额。差额办理历史仅薪酬管理人员可读。员工可查看本人异议答复历史。原工资条及原批次金额保持不变。

## 验证

接口测试覆盖未发布工资条拒绝、异议本人限制及重复在途拒绝、跨角色保密、正负差额方向、在途唯一、编制不得自审、未发布不可见、重复发布、不可取消已发布记录、旧版本冲突、异议关联已发布差额、历史访问拒绝、反向差额恢复原合计，以及本人晋升管理员后仍不得自利编制。

仍需企业提供真实薪酬政策、核定样例、实际角色清单及相关接口，完成业务验收后才能承载真实薪酬业务。
