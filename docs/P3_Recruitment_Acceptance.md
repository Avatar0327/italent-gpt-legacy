# P3 招聘与入职首轮闭环验收

日期：2026-09-07。

已实现岗位招聘需求、人数及依据、独立批准；候选人来源登记、联系邮箱字段权限；面试等级、推进建议与事实依据；录用申请、独立录用审批；HR登记候选人接受录用的书面依据；按计划日期办理入职；候选流程结束及需求关闭。

需求和录用审批限制为有组织权限的管理员/经理，禁止发起人审批自己的需求或录用。录用前必须有最近一次建议推进的面试记录。入职前须已批准并记录接受依据，禁止未来日期提前入职、重复建档和超批准人数。关闭需求前须完成或结束全部在途候选流程。

入职把员工新增、岗位/职级关联、任职历史、候选人状态、完整版本快照和两类审计放在同一个版本保护的D1事务中。任何一处失败都整体回滚。候选人姓名及邮箱来自已有候选记录，岗位来自已批准需求，不能在入职请求里替换为其他岗位。

沿用HR/经理组织权限；员工和纯审批人身份不授予招聘数据权限。联系邮箱和职级在列表及过程历史接口中按已有字段权限裁剪；没有联系邮箱权限的HR不能新写候选邮箱。

新增实际API集成测试：需求独立批准→候选人→面试门槛→面试→邮箱及历史字段裁剪→录用独立批准→接受依据→审计故障下入职整体回滚→成功原子建档→重复办理拒绝→超招聘人数拒绝→流程结束→需求关闭→员工不能访问招聘数据。与既有21项和此前P3的8项合计30项测试。类型检查通过，标准构建为保存发布门槛。

边界：尚未实现外部职位渠道、面试邀约/日历集成、候选人门户、完整Offer薪酬条款、电子签署、背调、测评供应商、AI推荐或入职材料批量采集。本轮不自动发送邮件、短信或邀请，不把HR登记接受依据伪称为候选人在线签署。原租户招聘提交细则仍需进一步逐页核实；生产使用须完成企业招聘/录用权限及正式材料规则验收。
