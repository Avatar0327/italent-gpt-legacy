# 课程阶段编排与进度报表

2026-09-07；原站仅核实学习计划有阶段编排概念与功能说明，以下具体限制及解锁规则为本系统独立设计。

| 维度 | 状态 |
|---|---|
| 需求核实 | 原站计划标签和说明已观察；具体解锁、推送及审批细则未核实 |
| 功能开发 | 草稿课程阶段、冻结、解锁、结项、可派发课程过滤及阶段进度报表 |
| 测试 | 新增2项集成场景，P3全套77项通过 |
| 生产验收 | 未完成 |

HR在培训项目草稿详情配置1至10阶段，总计最多20个已发布且不重复的课程版本，阶段名不重复。阶段顺序由配置顺序确定，启动后冻结。同阶段课程可并行；后续阶段派课/报名必须满足该员工此前所有阶段在本项目的学习任务已通过独立成果核验。仅提交、自报进度或项目外课程完成不解锁。没有配置阶段的旧培训继续按原方式办理。

阶段项目结项时，对已有非取消项目任务的参与人员核查全部课程，不因第一阶段任务全部完成而允许提前结束。全部任务取消的人员不在当前有效参与范围。已有未结束场次和未完成任务的结项门槛继续有效。经理仍须拥有项目组织管理范围，员工身份能查看项目不授予结项权限。

阶段报表只列当前可见、有非取消任务的人员：计划课程总数、已核验课程数、最早未完成阶段、该阶段已派发未完成和尚未派发。后二者互斥；未派发课程仍在总要求内。报表不推断应参训全员名单，不自动结项，普通员工不可访问管理报表。

验证：重复课程拒绝、经理配置拒绝、启动后冻结、未核验不能跳阶段、第一阶段完成仍不能结项、项目外完成不自动折抵、跨组织经理不能结项、完整流程成功；报表从零参与到部分派发、独立核验及全部课程完成，跨范围隔离。

尚未实现：多形式阶段、条件分支、批量规则派发、自动提醒、奖章和证书联动；旧课程版本全局唯一的领取规则仍适用，未提供历史课程折抵或重新领取机制。上线真实业务前须结合企业制度确认这些独立设计。

## 当前阶段批量派课增量
有项目组织管理范围的管理者可显式选择最多20人，为各人最早未完成阶段派发任务，单次最多20条新任务。已派发且非取消的同项目任务跳过；前序阶段未核验时不派发后续阶段。任何人员、课程、截止日、修订冲突或写入失败均整批不保存。测试验证第二条写入失败回滚、同修订两事件、重复拒绝、两人独立成果核验后下一阶段派发、旧修订无旁写。全套P3 78项通过。不是按规则定时自动派发，也不发送提醒；取消及跨项目既有课程仍遵循原版本唯一约束，报表仅标为无有效项目任务。
